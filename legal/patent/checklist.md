## Pass 3 自己レビュー記録

### 1周目: 新規性

- 請求項1は、単なるブラウザ操作又は単なる AI 連携ではなく、タブ単位明示許可、Gateway 経由の操作要求限定転送、origin 変更時自動失効を同一構成内に入れた。
- 請求項5は loopback only と外部中継サーバー非送信を明記し、商用クラウド連携型 prior art との差を明確化した。
- 請求項6は Manifest V3、全 URL host_permissions なし、activeTab による共有許可対象タブアクセスを明記し、全 URL 一括許可型拡張との差を明確化した。
- 請求項8は CDP 単独では既知であるため、請求項1の共有許可済みタブ限定構成に従属させた。
- 請求項9は JavaScriptCore in-process plugin と別プロセス plugin の双方を含む文言へ拡張した。
- 請求項11は Notion などの domain glob と transform 名の照合処理に限定し、単なる汎用プラグイン機構との差を出した。
- 請求項12は実装に存在しない完全自動ランダム操作生成を避け、記録、ドライラン、再生による反復操作検証又はモンキーテスト支援に限定した。

### 2周目: 進歩性

- prior art 1.1から1.3の商用ブラウザ AI 連携は、バックエンド通信又はブラウザ本体機能を前提とするため、loopback only、CLI 汎用インターフェース、ローカル監査ログの組合せを前面に出した。
- prior art 1.4から1.8の自動化フレームワークは、専用ブラウザ又はテスト用途が中心であるため、普段使いブラウザの共有許可済みタブのみを対象とする点を明細書に補強した。
- prior art 1.9から1.13の拡張機能データ漏洩事案は、全 URL 権限及び外部送信リスクの背景として位置付け、host_permissions なし及び外部中継非送信を効果に結び付けた。
- per-tab consent、CDP、loopback、plugin は個別には既知であるため、請求項1を中心に origin 変更時自動失効と許可管理部での操作要求限定転送を必須要素化した。
- token economy は特許性の中核要件ではなく、実施例及び効果の補強として位置付けた。

### 3周目: 明確性及び記載要件

- 「適切な」「外部の」等の広すぎる表現を避け、許可時 origin、現在 origin、共有許可済みタブ、ループバックインターフェース、ドメイン条件、変換名、ドライラン処理等の技術用語に置換した。
- 請求項1から14の各構成要素について、明細書【課題を解決するための手段】及び【発明を実施するための形態】に対応記載を設けた。
- 請求項7の書き込み操作承認は、明細書【0054】に読み取り操作と書き込み操作の分離として記載した。
- 請求項8の CDP 操作は、明細書【0055】に具体的 CDP メソッド例を記載した。
- 請求項11の per-domain plugin は、明細書【0058】及び【0059】に domain matcher と Notion plugin の実装例を記載した。

## 請求項別進歩性論点メモ

- 請求項1: per-tab 明示許可、操作要求限定転送、origin 変更時自動失効の組合せが中核である。
- 請求項2: タブ閉鎖時失効は単独では弱いが、請求項1の許可ライフサイクル補完要素である。
- 請求項3: 明示的取消しは単独では弱いが、popup と CLI の双方から同じ許可状態を失効できる点に実施価値がある。
- 請求項4: ローカル監査ログは、AI エージェント操作の事後追跡を可能にする業務利用上の補強要素である。
- 請求項5: loopback only と外部中継非送信は、商用クラウド型 prior art との差別化要素である。
- 請求項6: Manifest V3、全 URL host_permissions なし、activeTab の組合せは、全 URL 一括許可型拡張との差別化要素である。
- 請求項7: 書き込み操作承認は、読み取り共有許可とは別の安全境界を提供する。
- 請求項8: CDP 利用は既知であるが、共有許可済みタブ限定及び host_permissions 不要化と組み合わせる点に意味がある。
- 請求項9: 同一プロセス内 JavaScriptCore スクリプトと別プロセス plugin の双方を包含し、変換処理を Gateway 側に集約する点が実装と一致する。
- 請求項10: CLI を universal AI interface とすることで、特定 AI サービス又は MCP 実装への依存を避ける。
- 請求項11: domain glob と transform 名を用いて汎用変換より前に per-domain 変換を選択する点が Notion 実装と一致する。
- 請求項12: 記録、ドライラン、再生により、AI 由来の操作列を監査可能かつ再実行可能にする点が反復検証上の差分である。
- 請求項13: 請求項1のシステム構成を方法発明として保護する。
- 請求項14: 請求項13の処理をコンピュータに実行させるプログラムとして保護する。
