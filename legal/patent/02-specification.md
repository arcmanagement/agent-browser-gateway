# 明細書

【書類名】明細書

【発明の名称】

【0001】
注釈レイヤ及びドメイン変更時の自動失効を伴うタブ単位明示許可型ブラウザAI連携システム

【技術分野】

【0002】
本発明は、ブラウザ上のタブ内容を AI エージェント又は自動化プログラムに提供し、当該 AI エージェント又は自動化プログラムからブラウザ操作を実行可能にするブラウザ連携技術に関する。特に、本発明は、ユーザー端末上の普段使いのブラウザにおいて、ユーザーが明示的に許可したタブのみを対象として AI エージェントとの連携を行い、許可時 origin からの変更に応じて共有許可を自動失効させ、さらに当該タブ上で AI エージェントの参照対象又は操作対象を注釈レイヤにより視覚化するローカルゲートウェイ技術に関する。

【背景技術】

【0003】
近年、AI エージェントがブラウザ上の情報を読み取り、フォーム入力、クリック、スクロール、ファイル添付等の操作を支援する技術が用いられている。商用ブラウザ又はブラウザ拡張機能には、ページ内容をクラウド上の AI サービスへ送信する構成、又はブラウザ内蔵 AI 機能を用いて現在ページを要約又は操作する構成が存在する。また、ヘッドレスブラウザ、自動テスト用ドライバ、リモート制御フレームワーク等の自動化フレームワークは、ブラウザをプログラムから制御するために広く利用されている。さらに、ユーザーが画面上の対象を人間同士の会話と同様に指示するため、スクリーンショット又はブラウザ画面上に注釈を付与し、AI エージェントに当該注釈を参照させる操作体験が重要になっている。

【0004】
一方で、既存のブラウザ AI 連携技術には、ユーザーが普段利用しているブラウザプロファイル及びログイン状態をそのまま用いながら、AI エージェントへ見せるタブをタブ単位で明示的に限定し、かつタブの origin 変更、タブ閉鎖、又は明示的取消しによって当該共有許可を自動的に失効させる構成が十分に提供されていない。さらに、ブラウザ拡張機能に全 URL 一括許可を付与する構成、又はクラウド中継サーバーへページ内容を送信する構成では、閲覧履歴、業務データ、顧客情報、認証済みページ内容等の漏洩リスクが残る。

【0005】
過去には、便利なブラウザ拡張機能が買収、所有者変更、又は方針変更により閲覧データを送信する事案が生じている。したがって、ブラウザと AI エージェントとの連携においては、コード監査可能性、ローカル完結性、操作履歴の記録、ユーザーが選択したタブ以外を AI エージェントから不可視にする技術的境界、及び AI エージェントが参照又は操作しようとする対象をユーザーが視覚的に確認できるフィードバックが重要となる。AI ブラウザ又はブラウザ相当環境では、標準的なブラウザ拡張機能 API の host permission 挙動が一般的なブラウザと異なる場合があり、注釈レイヤを複数の実行経路で安定して表示できる相互運用性も求められる。

【発明の概要】

【発明が解決しようとする課題】

【0020】
既存の商用ブラウザ AI 連携技術は、ページ内容をクラウドサービスへ送信する構造、又は提供者のバックエンドと連携する構造を含む場合がある。このような構造では、ユーザー端末から外部ネットワークへブラウザデータが流れることを構造的に排除できない。

【0021】
既存のブラウザ自動化フレームワークは、テスト又はスクレイピング用途を主目的とし、専用ブラウザインスタンス、リモートデバッグポート、又は自動化プロファイルを用いることが多い。このため、ユーザーが通常利用しているブラウザプロファイル、ログイン状態、拡張機能、及び業務画面をそのまま対象にしにくい。また、ユーザーが AI エージェントに見せるタブをタブ単位で明示的に選択し、共有中のタブが別 origin に遷移した時点で自動的に見えなくする許可ライフサイクルが組み込まれていない。

【0022】
さらに、ブラウザ拡張機能に全 URL 一括許可を付与する構成では、拡張機能又は当該拡張機能と通信するプログラムが、ユーザーの意図しないページへアクセスする余地が生じる。AI エージェントがプロンプトインジェクション等により未共有タブの内容を要求した場合にも、タブ単位の技術的境界がなければ、意図しない情報漏洩を防止しにくい。

【0023】
本発明の課題は、ユーザーの普段使いブラウザ上のタブを AI エージェントに連携させるにあたり、ユーザーが明示的に許可したタブのみを対象とし、当該タブの origin 変更、タブ閉鎖、又は明示的取消しに応じて共有許可を失効させ、かつブラウザデータを外部ネットワークへ送信しないローカル完結型のブラウザAI連携システムを提供することである。さらに、本発明の課題は、共有許可済みタブ上でユーザーが領域、テキスト、又は DOM 要素を注釈として指定し、AI エージェントが当該注釈を構造化データとして取得できるようにしつつ、対象が安定した DOM、任意の視覚領域、又は複数 DOM 要素にまたがるテキストである場合を区別して取り扱うことである。

【課題を解決するための手段】

【0024】
本発明の第1の態様は、ユーザー端末上で動作するブラウザと、当該ユーザー端末上で動作する AI エージェントとを連携させるブラウザAI連携システムである。当該システムは、ブラウザ上で動作し、タブ単位の共有許可を管理するブラウザ拡張機能と、ユーザー端末上で動作し、ブラウザ拡張機能との間でローカル通信を行う Gateway モジュールと、AI エージェントから呼び出され、Gateway モジュールに操作要求又は注釈要求を送信するコマンドラインインターフェースとを備える。

【0025】
ブラウザ拡張機能は、ユーザーが特定のタブについて明示的な共有許可操作を行った場合に限り、当該特定のタブを共有許可済みタブとして Gateway モジュールに登録する。Gateway モジュールは、コマンドラインインターフェースから受信した操作要求又は注釈要求が共有許可済みタブを対象とする場合に限り、当該操作要求又は注釈要求をブラウザ拡張機能に転送する。ブラウザ拡張機能は、共有許可済みタブの現在の origin が、明示的な共有許可操作の時点で記録された許可時 origin と異なる origin へ変更されたことを検知した場合に、当該共有許可済みタブの共有許可を失効させる。

【0026】
本発明の第2の態様では、ブラウザ拡張機能は、共有許可済みタブが閉じられたことを検知した場合に共有許可を失効させる。本発明の第3の態様では、ブラウザ拡張機能又はコマンドラインインターフェースは、ユーザーによる明示的な取消操作を受け付け、Gateway モジュールは当該取消操作に応じて失効要求をブラウザ拡張機能に送信する。

【0027】
本発明の第4の態様では、Gateway モジュールは、共有許可の付与、共有許可の失効、読み取り操作、注釈操作、及び書き込み操作を含む操作履歴をユーザー端末上の監査ログに JSONL 形式で追記し、監査ログを格納するディレクトリ及びファイルのアクセス権限を所有者ユーザーのみに限定する。本発明の第5の態様では、Gateway モジュールはブラウザ拡張機能との通信待受をループバックインターフェースに限定し、さらに WebSocket 接続要求の Origin がブラウザ拡張機能 origin であることを検証し、通常の Web ページ origin 等からの接続要求を拒否する。

【0028】
本発明の第6の態様では、ブラウザ拡張機能は Manifest V3 形式で構成され、全 URL を対象とする host_permissions を有さず、ユーザー操作に基づく activeTab 権限により共有許可対象のタブに対するアクセスを取得する。本発明の第7の態様では、読み取り操作と書き込み操作とで承認フローを分離し、書き込み操作については内容をユーザーに提示し、ユーザーの承認を受けた場合に限り実行する。書き込み操作には、一時的な DOM 差し替え、ファイル添付、ナビゲーション、又は座標操作を含めてよい。

【0029】
本発明の第8の態様では、ブラウザ拡張機能は Chrome DevTools Protocol を用いて、DOM 読み取り、スクリーンショット取得、コンソールログ取得、ネットワークログ取得、座標クリック、スクロール、ドラッグ、キー送信、ファイル入力要素へのファイル設定、及び共有許可済みタブ上での注釈レイヤ実行の少なくとも一つを実行する。本発明の第9の態様では、Gateway モジュールは、ブラウザ拡張機能から受信したタブ内容を、AI エージェントへ返送する前に、同一プロセス内、又は別プロセスで動作する外部スクリプト若しくは実行ファイルにより変換する変換実行部を備える。

【0030】
本発明の第10の態様では、コマンドラインインターフェースは、共有許可済みタブの一覧取得、タブ内容の読み取り、スクリーンショット取得、要素説明、テーブル抽出、ネットワークログ取得、注釈レイヤの開始、停止、消去及び注釈一覧取得、クリック、入力、キー送信、ナビゲーション、スクロール、ドラッグ、ファイル添付、一時的な DOM 差し替え、待機、共有許可の取消し、及び監査ログの取得の少なくとも一つをシェルコマンドとして AI エージェントに提供する。本発明の第11の態様では、Gateway モジュールは、ドメイン条件及び変換名を含むプラグイン定義を読み込み、共有許可済みタブの URL がドメイン条件に合致する場合に、汎用変換より前に当該ドメイン条件に対応する変換処理を実行する。

【0031】
本発明の第12の態様では、コマンドラインインターフェースは、共有許可済みタブに対する複数の操作をフローとして記録し、当該フローを実行前に表示するドライラン処理と、当該フローを共有許可済みタブに対して再生する再生処理とを提供し、反復操作検証又はモンキーテスト支援に用いられる操作列を生成及び再実行可能にする。本発明の第13の態様では、ブラウザ拡張機能は、共有許可済みタブ上に注釈レイヤを描画し、ユーザーによる領域指定、ユーザーによるテキスト選択、又はコマンドラインインターフェースからの注釈追加要求を注釈入力として受け付け、番号及びコメントを共有許可済みタブ上に視覚的に表示する。

【0032】
本発明の第14の態様では、ブラウザ拡張機能は、領域指定に係る注釈を DOM 注釈又はスクリーンショット領域注釈に分類し、テキスト選択に係る注釈をテキストアンカーを含むテキスト注釈に分類する。本発明の第15の態様では、ブラウザ拡張機能は、ブラウザ拡張機能 API によるスクリプト実行が拒否された場合に、デバッガ接続を確立したうえで Chrome DevTools Protocol の Runtime.evaluate により注釈レイヤを実行する。本発明の第16の態様は、前記システムに対応する方法である。本発明の第17の態様は、前記方法における注釈分類及び注釈データ保持の方法である。本発明の第18の態様は、ユーザー端末上のコンピュータに前記方法を実行させるプログラムである。

【発明の効果】

【0033】
本発明によれば、ユーザーが明示的に許可したタブのみが AI エージェントから見えるため、ブラウザ全体又は全 URL に対する一括許可を前提とする構成に比べて、意図しないページ内容の露出を抑制できる。

【0034】
本発明によれば、共有許可済みタブが許可時 origin と異なる origin へ移動した場合に共有許可が自動失効するため、ユーザーが別サイト又は機密サイトへ遷移した後も AI エージェントが当該タブを継続して閲覧又は操作する事態を防止できる。

【0035】
本発明によれば、Gateway モジュールがループバックインターフェースに限定して動作し、外部ネットワーク上の中継サーバーへタブ内容を送信しないため、クラウド中継又はテレメトリに起因するデータ漏洩リスクを構造的に低減できる。

【0036】
本発明によれば、Gateway モジュールが WebSocket 接続要求の Origin をブラウザ拡張機能 origin に限定するため、通常の Web ページ上の JavaScript がループバック WebSocket に接続して Gateway モジュールへメッセージを送信する攻撃面を低減できる。

【0037】
本発明によれば、Manifest V3 形式のブラウザ拡張機能が全 URL を対象とする host_permissions を有さず、共有許可対象タブに対して必要な範囲でアクセスするため、ブラウザ拡張機能の権限を最小化できる。

【0038】
本発明によれば、共有許可済みタブ上に注釈レイヤを描画し、領域、DOM 要素、テキスト選択、及び CLI 由来の注釈入力を構造化して AI エージェントへ返送できるため、AI エージェントの参照対象又は操作対象をユーザーが視覚的に確認しながら作業できる。また、監査ログ、書き込み操作承認、及びプラグイン変換を Gateway モジュール側で管理するため、業務利用における操作追跡、データ最小化、及びドメイン別のノイズ除去を実現できる。

【発明を実施するための形態】

【0048】
以下、本発明の実施形態を説明する。以下の実施形態は例示であり、本発明はこれらの構成に限定されない。

【0049】
図1に示すように、本実施形態のブラウザAI連携システム1は、ブラウザ拡張機能10、Gateway モジュール20、コマンドラインインターフェース30、ブラウザタブ40、プラグイン50、監査ログ60、及び許可管理部70を備える。ブラウザ拡張機能10は、ブラウザタブ40に対するユーザーの明示的な共有許可操作を受け付ける。Gateway モジュール20は、ブラウザ拡張機能10とコマンドラインインターフェース30との間に位置し、許可管理部70により共有許可済みタブを管理する。コマンドラインインターフェース30は、AI エージェント90からシェルコマンドとして呼び出される。

【第1実施形態】

【0050】
第1実施形態では、ユーザー端末はデスクトップオペレーティングシステムを搭載したコンピュータであり、ブラウザは WebExtensions 互換ブラウザである。Gateway モジュール20は、メニューバー又はシステムトレイに常駐するネイティブアプリケーションとして実装される。Gateway モジュール20は、ブラウザ拡張機能10との通信のために `127.0.0.1:8765` 上の WebSocket エンドポイントを待ち受け、コマンドラインインターフェース30との通信のために Unix Domain Socket を用いる。Unix Domain Socket のファイル権限は所有者ユーザーのみがアクセス可能な権限に設定される。

【0051】
ブラウザ拡張機能10は Manifest V3 の拡張機能であり、`activeTab`、`scripting`、`tabs`、`storage`、`debugger`、及び `alarms` 等の権限を用いる。一方、ブラウザ拡張機能10は `host_permissions` に全 URL 一括許可を含めない。ブラウザ拡張機能10は、ユーザーが拡張機能のポップアップで「このタブを共有」に相当する操作を行った場合に、当該タブのタブ ID、URL、タイトル、origin、共有許可時刻を Gateway モジュール20へ送信する。

【0052】
許可管理部70は、共有許可済みタブのタブ ID、extension ID、URL、タイトル、許可時 origin、及び共有許可時刻を保持する。AI エージェント90からコマンドラインインターフェース30を介して操作要求が送られると、Gateway モジュール20は、対象タブが許可管理部70に登録されているかを判定する。登録されていない場合、Gateway モジュール20は操作要求を拒否し、ブラウザ拡張機能10へ転送しない。

【0053】
図2に示すように、共有許可状態は、非共有状態、共有許可操作中状態、共有中状態、及び失効状態を含む。非共有状態では AI エージェント90からタブ内容を取得できない。共有許可操作中状態では、ユーザーがポップアップ等で共有操作を実行する。共有中状態では、共有許可済みタブに対する読み取り、注釈、又は操作が可能である。失効状態では、当該タブは共有許可済みタブではなくなる。

【0054】
図3に示すように、ブラウザ拡張機能10は、共有許可済みタブ40の URL 更新イベント又はナビゲーションイベントを監視する。共有許可済みタブ40の現在 origin が許可時 origin と異なることを検知した場合、ブラウザ拡張機能10は共有許可を削除し、Gateway モジュール20へ失効通知を送信する。Gateway モジュール20は、許可管理部70から当該タブを削除し、監査ログ60に失効理由として origin 変更を追記する。タブ閉鎖及びユーザーの明示的取消しについても同様に、共有許可を削除し、失効理由を監査ログ60に記録する。

【0055】
図4に示すように、AI エージェント90は、例えば `abg read <tab>`、`abg annotate <tab> --start`、`abg click <tab> --selector <css>`、`abg fill <tab> --selector <css> --value <text>` 等のシェルコマンドを実行する。コマンドラインインターフェース30は、操作要求又は注釈要求を JSON 形式のメッセージとして Unix Domain Socket 経由で Gateway モジュール20へ送信する。Gateway モジュール20は許可管理部70で対象タブの共有許可を確認し、許可がある場合に WebSocket 経由でブラウザ拡張機能10へ操作要求又は注釈要求を転送する。ブラウザ拡張機能10は、Chrome DevTools Protocol 又は構造化されたスクリプト注入によりブラウザタブ40を読み取り、注釈し、又は操作し、結果を逆経路で AI エージェント90へ返す。

【0056】
読み取り操作には、DOM 読み取り、スクリーンショット取得、コンソールログ取得、テーブル抽出、要素説明、ネットワークログ取得、及び注釈一覧取得等が含まれる。書き込み操作には、クリック、入力、キー送信、ナビゲーション、スクロール、ドラッグ、ファイル添付、及び一時的な DOM 差し替え等が含まれる。書き込み操作については、ブラウザ拡張機能10が操作の内容、対象タブ、対象セレクタ、入力値又は座標等をユーザーに提示する承認ウィンドウを開き、ユーザーが承認した場合に限り実行する構成とできる。

【0057】
Chrome DevTools Protocol を用いる場合、ブラウザ拡張機能10は、DOM 読み取り又は注釈レイヤ実行に `Runtime.evaluate` を用い、スクリーンショット取得に `Page.captureScreenshot` を用い、クリック、スクロール、ドラッグ、キー送信に `Input.dispatchMouseEvent` 又は `Input.dispatchKeyEvent` を用い、ファイル添付に `DOM.setFileInputFiles` を用いる。これにより、全 URL 一括 host_permissions を用いずに、共有許可済みタブに限定した操作を実行できる。

【0058】
Gateway モジュール20は、すべての共有許可付与、失効、読み取り操作、注釈操作、及び書き込み操作を監査ログ60へ JSONL 形式で追記する。監査ログ60には、時刻、タブ ID、URL、操作種別、失効理由、及び可能な場合には呼び出し元 agent 識別子が含まれる。監査ログ60はユーザー端末上に保存され、外部ネットワークへ送信されない。

【0059】
図5に示すように、従来型の全 URL 一括許可型拡張機能では、拡張機能が多数の origin へ継続的にアクセス可能であり、所有者変更、更新、又はバックエンド連携によりデータ漏洩リスクが生じる。これに対し、本実施形態では、ブラウザ拡張機能10が全 URL 一括 host_permissions を持たず、ユーザーが共有許可したタブのみを対象とし、origin 変更により共有許可を自動失効させる。この組合せにより、AI エージェント90がアクセスできるブラウザ情報の範囲を技術的に制限できる。

【0060】
図6に示すように、Gateway モジュール20はプラグイン50をロードする。プラグイン50は、Gateway モジュール20と同一プロセス内の JavaScriptCore VM で動作する JavaScript スクリプトであってよい。また、別プロセスで動作する外部スクリプト又は実行ファイルであってもよい。プラグイン50は、`abg.registerTransform` に相当するホスト API により変換名を登録し、Gateway モジュール20はブラウザ拡張機能10から取得した HTML 等のタブ内容を AI エージェント90へ返す前に当該変換を実行する。

【0061】
プラグイン50の第1例は `markdown-plugin` であり、HTML を Markdown へ変換する。プラグイン50の第2例は `notion-plugin` であり、`notion.so`、`www.notion.so`、任意のサブドメインの `notion.so`、及び任意のサブドメインの `notion.site` に合致する URL について、サイドバー、トップバー、ポップオーバー、スクリプト、スタイル、及び Notion 固有の管理属性を除去し、本文を compact Markdown に変換する。Gateway モジュール20は、共有許可済みタブの URL がプラグイン定義のドメイン条件に合致する場合に、汎用 Markdown 変換より前に当該ドメイン別変換を実行する。

【0062】
コマンドラインインターフェース30は、反復操作フローを扱う機能を備えてよい。具体的には、共有許可済みタブに対して発行された読み取り、スクリーンショット、クリック、入力、キー送信、ナビゲーション、スクロール、ドラッグ、ファイル添付、待機等の操作を JSON 形式のフローとして記録する。また、記録済みフローを実行せずに表示するドライラン処理と、共有許可済みタブに対して再生する再生処理を提供する。これにより、AI エージェント90又はユーザーは、反復操作検証、モンキーテスト支援、業務手順再現、及び操作列の監査に用いることができる。

【0063】
本実施形態では、AI エージェント90は、対話型コーディングエージェント、統合開発環境内のエージェント、端末上の自動化エージェント、又は社内開発エージェント等であってよい。AI エージェント90は、コマンドラインインターフェース30をシェルコマンドとして実行可能であればよく、特定の AI サービス、特定のクラウド API、又は特定のクライアント実装に限定されない。スキルファイル、手順ファイル、又はツール定義ファイルをインストールする構成では、当該ファイルがコマンドラインインターフェース30の使い方を AI エージェント90に提示する。

【第2実施形態】

【0064】
第2実施形態は、注釈レイヤ統合構成である。図8に示すように、ブラウザ拡張機能10は、共有許可済みタブ40上に注釈レイヤ100を描画する。注釈レイヤ100は、ブラウザタブ40の通常 DOM とは分離されたレイヤとして構成され、番号付き注釈、コメント、ツールバー、領域指定用のドラフト矩形、及びコメント編集 UI を含む。注釈レイヤ100は、共有許可済みタブ40に対してのみ開始でき、未共有タブではポップアップ及びコマンドラインインターフェース30のいずれからも開始されない。

【0065】
注釈レイヤ100は、Area モード及び Text モードを有する。Area モードでは、ユーザーがブラウザタブ40上でドラッグした矩形領域、又はクリックした点を注釈入力として受け付ける。Text モードでは、ユーザーが複数 DOM 要素にまたがる本文を選択した場合であっても、選択文字列を注釈入力として受け付ける。ユーザーは、注釈入力にコメントを付与し、Done ボタン又は Escape キーにより注釈レイヤ100のキャプチャを停止できる。停止後も注釈データ110は保持され、AI エージェント90はコマンドラインインターフェース30により当該注釈データ110を取得できる。

【0066】
ブラウザ拡張機能10は、Area モードで指定された領域について、領域の中心点、対象要素の表示矩形、安定した属性、及び意味のある要素種別を用いて、当該領域が安定した DOM セレクタに対応するかを判定する。安定した DOM セレクタに対応する場合、ブラウザ拡張機能10は当該注釈を DOM 注釈として分類し、対象要素のセレクタ、セレクタ品質、タグ名、表示文字列、色、背景色、フォントサイズ及びフォントファミリ等を注釈データ110に含める。canvas、video、又は曖昧な wrapper のように安定した DOM 対象を推定しにくい場合、ブラウザ拡張機能10は当該注釈をスクリーンショット領域注釈として分類し、ビューポート座標及びページ座標を注釈データ110に含める。

【0067】
ブラウザ拡張機能10は、Text モードで指定された選択文字列について、選択文字列、当該選択文字列のルート要素セレクタ、DOM Range の開始及び終了位置、ハイライト断片、並びに再特定用のインデックスを含むテキストアンカーを注釈データ110に含める。テキスト注釈は矩形枠ではなく、選択文字列の行ごとのハイライトとして注釈レイヤ100上に表示される。これにより、AI エージェント90は、スクリーンショット領域としてではなく、純粋なテキストデータとして選択内容を受け取ることができる。

【0068】
DOM 注釈及びテキスト注釈は、セレクタ又はテキストアンカーへの追従性を維持するため、注釈レイヤ100上で移動又はリサイズされない。一方、スクリーンショット領域注釈は、任意の視覚領域を示すため、ドラッグによる移動及び辺又は角のハンドルによるリサイズを許容する。ブラウザ拡張機能10は、スクロール、リサイズ、iframe 内スクロール、又はレスポンシブレイアウト変更に応じて注釈レイヤ100を再描画し、各注釈のビューポート座標を更新する。

【0069】
コマンドラインインターフェース30は、注釈レイヤ100について、開始、停止、消去、一覧取得、CSS セレクタによる DOM 注釈追加、及びビューポート座標による領域注釈追加を提供する。領域注釈追加の結果がスクリーンショット領域注釈である場合、コマンドラインインターフェース30は当該領域に対応するスクリーンショットを保存してもよい。注釈一覧の戻り値には、注釈種別、コメント、ビューポート座標、ページ座標、DOM セレクタ、対象要素メタデータ、選択文字列、テキストアンカー、URL、タイトル、及び作成時刻の少なくとも一つが含まれる。

【0070】
注釈レイヤ100は、AI エージェント90による操作の事前確認にも利用できる。例えば、AI エージェント90がボタン、ロゴ、入力欄、又は任意の視覚領域を操作又は差し替えの対象として提案する場合、ユーザーは当該対象を注釈として指定し、AI エージェント90は注釈データ110に含まれるセレクタ又は座標を用いて後続の読み取り、スクリーンショット取得、一時的な DOM 差し替え、又は承認付き書き込み操作を行うことができる。これにより、人間が「ここ」と指示した対象を、AI エージェント90が構造化された対象情報として扱うことができる。

【0071】
ブラウザ拡張機能10は、注釈レイヤ100を実行する際、まずブラウザ拡張機能 API によるスクリプト実行を試行する。当該スクリプト実行が、AI ブラウザ又はブラウザ相当環境における host permission 挙動により拒否された場合、ブラウザ拡張機能10は、共有許可済みタブ40に対してデバッガ接続を確立し、Chrome DevTools Protocol の `Runtime.evaluate` により注釈レイヤ100を実行する。一般的なブラウザ環境ではブラウザ拡張機能 API によるスクリプト実行を優先し、必要時のみ CDP 経路へフォールバックする。

【第3実施形態】

【0072】
第3実施形態は、ループバック WebSocket セキュリティ強化構成である。図9に示すように、Gateway モジュール20は、WebSocket 接続要求を受けた場合、接続を実質的に受け入れてメッセージ処理を開始する前に、Origin 検証部120により当該接続要求の Origin を検証する。Origin 検証部120は、Origin の scheme が `chrome-extension`、`moz-extension`、又は `safari-web-extension` のいずれかであり、かつ host が存在し、ユーザー情報、パス、クエリ、及びフラグメントを含まない場合に限り、ブラウザ拡張機能 origin と判定する。

【0073】
Origin 検証部120は、Origin が欠落している場合、空文字列である場合、`http` 又は `https` の通常 Web ページ origin である場合、`file` origin である場合、`null` origin である場合、又はブラウザ拡張機能 origin に似せた不正な scheme、パス、クエリ若しくはユーザー情報を含む場合には、当該 WebSocket 接続要求を拒否する。これにより、通常の Web ページ上のスクリプトが `ws://127.0.0.1:8765/ws` に接続して Gateway モジュール20を操作する経路を遮断できる。

【0074】
Gateway モジュール20は、アプリケーションサポートディレクトリ、ログディレクトリ、Unix Domain Socket、及び監査ログ60について、所有者ユーザーのみがアクセス可能な権限を設定する。例えば、アプリケーションサポートディレクトリ及びログディレクトリは所有者ユーザーのみがアクセス可能な権限とし、監査ログ60は所有者ユーザーのみが読み書き可能な権限とする。監査ログ60は JSONL 形式で追記され、読み取り、書き込み、注釈、共有許可付与、失効、及び接続状態の変化を記録する。

【0075】
Gateway モジュール20に対応するテストは、ブラウザ拡張機能 origin を許可する場合、通常 Web ページ origin、file origin、null origin、欠落 Origin を拒否する場合、及びブラウザ拡張機能 origin に似せた不正形式を拒否する場合を含む。これにより、Origin 検証部120の境界条件を実装段階で検証できる。

【第4実施形態】

【0076】
第4実施形態では、ブラウザは複数種類の WebExtensions 互換ブラウザ、又はこれに準ずる拡張機能機構を有するブラウザであってよい。ブラウザ拡張機能10は、各ブラウザの拡張機能 API に応じて実装される。Chrome DevTools Protocol に相当するプロトコル又はブラウザ固有のデバッグ API が利用可能な場合、ブラウザ拡張機能10は当該プロトコルを用いて読み取り、注釈、又は操作を実行する。利用可能でない場合、ブラウザ拡張機能10は、共有許可済みタブに対する構造化された限定的なスクリプト注入により読み取り、注釈、又は操作を実行する。

【0077】
Gateway モジュール20は、デスクトップオペレーティングシステム、モバイルオペレーティングシステム、又は組込み環境上で動作してもよい。コマンドラインインターフェース30は、Unix Domain Socket に限らず、名前付きパイプ、ローカル TCP ソケット、標準入出力、又は OS 固有のローカル IPC を用いて Gateway モジュール20と通信してよい。ただし、ブラウザタブ40の内容を外部ネットワーク上の中継サーバーへ送信しないローカル完結性を維持する。

【実施例1】

【0078】
実施例1では、通常のブラウザタブで開いている日本語 CMS 記事をユーザーがブラウザ拡張機能10のポップアップから共有許可し、AI エージェント90が `abg read <tab> --selector article --format markdown` に相当するコマンドを実行した。比較対象として、ブラウザ自動化フレームワークによるページ全体 HTML 取得、`article` 要素の `innerHTML` 取得、及び `article` 要素の `innerText` 取得を用いた。測定対象は公開記事に係る ABG repo benchmark である。

【0079】
測定結果は次のとおりである。

| 方法 | 文字数 | 概算トークン数 | 構造 |
|---|---:|---:|:---:|
| ページ全体 HTML 取得 | 124,476 | 約50,000 | preserved (massive overhead) |
| `article` 要素 `innerHTML` 取得 | 42,070 | 約17,000 | preserved (with overhead) |
| `abg read N --selector article --as-markdown` | 11,780 | 約5,900 | preserved (clean) |
| `article` 要素 `innerText` 取得 | 6,543 | 約3,800 | lost (no headings / links / lists) |

【0080】
この結果から、`abg read N --selector article --as-markdown` は、ページ全体 HTML 取得と比較して、文字数ベースで約90.5%削減し、概算トークン数ベースで約88%削減した。一方で、`innerText` 取得と異なり、見出し、リンク、リスト等の構造は保持された。したがって、本実施形態は、共有許可済みタブに限定した安全な連携に加え、AI エージェント90へ渡す文脈量を大幅に低減する効果を有する。

【実施例2】

【0081】
実施例2では、ナレッジベース型ページの fixture を用い、汎用 `markdown-plugin` と、ドメイン別プラグインとを比較した。ドメイン別プラグインは、プラグイン定義において特定のドメイン条件を有し、Gateway モジュール20が共有許可済みタブの URL と当該ドメイン条件とを照合したうえで、汎用変換より前にドメイン別変換を実行する。

【0082】
測定結果は次のとおりである。

| 方法 | 文字数 | 概算トークン数 | raw 比削減率 |
|---|---:|---:|---:|
| Raw knowledge-base page HTML | 2,209 | 約553 | - |
| Generic markdown-plugin | 1,242 | 約311 | 44% |
| Domain-specific transform | 709 | 約178 | 68% |

【0083】
この結果から、ドメイン別プラグイン50は、汎用 HTML 変換よりもさらにページ固有の不要要素を削減し、raw HTML 比で約68%のトークン削減を実現した。これにより、AI エージェント90は、アプリケーションのサイドバー、ポップオーバー、スクリプト、スタイル等のノイズではなく、業務上意味のある本文に集中できる。

本発明は、AI エージェントを用いた業務支援、Web アプリケーションの運用保守、カスタマーサポート、データ入力、監査、テスト、コンプライアンス対応、社内業務自動化、及び委託先又は外部パートナーとの共同作業に利用できる。特に、認証済み業務画面、顧客データ、管理画面、社内ナレッジベース等を扱う場面において、ユーザーが明示的に許可したタブのみを AI エージェントに共有し、origin 変更時に共有許可を自動失効させ、操作履歴をローカルに記録し、注釈レイヤにより対象を視覚的に確認することにより、業務上のデータガバナンスを保ちながら AI エージェントによる支援を導入できる。
