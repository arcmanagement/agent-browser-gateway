# 明細書

【書類名】明細書

【発明の名称】ブラウザＡＩ連携システム

【技術分野】

【0001】
本発明は、ブラウザ上のタブ内容を AI エージェント又は自動化プログラムに提供し、当該 AI エージェント又は自動化プログラムからブラウザ操作を実行可能にするブラウザ連携技術に関する。特に、本発明は、ユーザーが明示的に許可したタブのみを対象として AI エージェントとの連携を行い、許可時の取得対象識別情報からの変更に応じて共有許可を自動失効させ、さらに当該タブ上で AI エージェントの参照対象又は操作対象を注釈レイヤにより視覚化するブラウザ AI 連携技術に関する。本発明において、Gateway モジュールは、ブラウザ操作連携機能と AI エージェントとの間で要求の中継、対象確認、共有許可管理、変換、監査記録、又はこれらに相当する処理の少なくとも一つを行う仲介機能をいう。ブラウザ、AI エージェント及び Gateway モジュールは、同一の情報処理装置上に配置されてもよく、互いに通信可能な複数の情報処理装置上に分散配置されてもよく、Gateway モジュールは、ブラウザ内、ブラウザのアドオン機構内、オペレーティングシステム内、AI エージェント実行環境内、ネイティブアプリケーション内、サーバー上、クラウド環境上、又はこれらの組み合わせとして実装されてもよい。

【背景技術】

【0002】
近年、AI エージェントがブラウザ上の情報を読み取り、フォーム入力、クリック、スクロール、ファイル添付等の操作を支援する技術が用いられている。商用ブラウザ又はブラウザ操作連携機能には、ページ内容をクラウド上の AI サービスへ送信する構成、又はブラウザ内蔵 AI 機能を用いて現在ページを要約又は操作する構成が存在する。例えば、非特許文献1ないし非特許文献4には、ブラウザ又はブラウザ拡張を介して AI がページ内容を参照し、又はブラウザ上の操作を支援する技術が記載されている。また、ヘッドレスブラウザ、自動テスト用ドライバ、リモート制御フレームワーク等の自動化フレームワークは、ブラウザをプログラムから制御するために広く利用されている。さらに、ユーザーが画面上の対象を人間同士の会話と同様に指示するため、スクリーンショット又はブラウザ画面上に注釈を付与し、AI エージェントに当該注釈を参照させる操作体験が重要になっている。例えば、特許文献1ないし特許文献5及び特許文献7には、AI、生成 AI、業務画面、UI 要素、RPA、自動化操作又は操作支援に関する技術が記載されている。また、特許文献6には、ウェブブラウザ内でドキュメントのアノテーションを作成、整理、表示又は接続する技術が記載されている。

【0003】
一方で、既存のブラウザ AI 連携技術には、ユーザーが普段利用しているブラウザプロファイル及びログイン状態をそのまま用いながら、AI エージェントへ見せるタブをタブ単位で明示的に限定し、かつタブの取得対象識別情報の変化、タブが閉じられること、又は明示的取消しによって当該共有許可を自動的に失効させる構成が十分に提供されていない。さらに、ブラウザ操作連携機能に包括的なアクセス許可を付与する構成、又はタブ単位の共有許可境界を持たずに中継サーバーへページ内容を送信する構成では、閲覧履歴、業務データ、顧客情報、認証済みページ内容等の漏洩リスクが残る。また、どのブラウザ内容又は変換後内容が AI エージェントへ返送され、どの操作要求又は操作コマンドが Gateway を通過したかが記録されない場合、情報漏洩、誤操作又はプロンプトインジェクション発生時の原因切り分けが困難になる。

【0004】
過去には、便利なブラウザ操作連携機能が買収、所有者変更、又は方針変更により閲覧データを送信する事案が生じている。したがって、ブラウザと AI エージェントとの連携においては、コード監査可能性、通信経路及びデータ送信先の制御可能性、操作履歴の記録、ユーザーが選択したタブ以外を AI エージェントから不可視にする技術的境界、及び AI エージェントが参照又は操作しようとする対象をユーザーが視覚的に確認できるフィードバックが重要となる。AI ブラウザ又はブラウザ相当環境では、標準的なブラウザアドオン API のホストアクセス権限の挙動が一般的なブラウザと異なる場合があり、注釈レイヤを複数の実行経路で安定して表示できる相互運用性も求められる。

【発明の概要】

【発明が解決しようとする課題】

【0021】
既存の商用ブラウザ AI 連携技術は、ページ内容をクラウドサービスへ送信する構造、又は提供者のバックエンドと連携する構造を含む場合がある。このような構造では、ユーザーが明示的に選択したタブのみに対象を限定する技術的境界、通信経路及び送信先の制御、並びにブラウザ内容、変換後内容、操作要求及び応答内容の送受信に関する監査可能性が十分でない場合がある。

【0022】
既存のブラウザ自動化フレームワーク又はブラウザ操作共有ツール、例えば Playwright MCP、Browser-use 等は、テスト、スクレイピング、又は一時的な自動操作用途を主目的とする。これらは、専用ブラウザインスタンス、リモートデバッグポート、又は自動化プロファイルを用いることが多い。このため、ユーザーが普段の業務又は生活で利用しているブラウザプロファイル、ログイン状態、アドオン機能、及び業務画面を、AI エージェントへ簡単に共有する用途には不便である。また、ユーザーが AI エージェントに見せる対象をタブ単位又は表示対象単位で明示的に選択し、共有中の対象が許可時とは異なる取得対象へ遷移した時点で自動的に見えなくする許可ライフサイクルが組み込まれていない。

【0023】
さらに、ブラウザ操作連携機能に包括的なページアクセス許可を付与する構成では、当該機能と通信するプログラムが、ユーザーの意図しないページへアクセスする余地が生じる。AI エージェントがプロンプトインジェクション等により未共有タブの内容を要求した場合にも、タブ単位の技術的境界がなければ、意図しない情報漏洩を防止しにくい。

【0024】
本発明の課題は、専用の自動化用ブラウザ環境又は特定のブラウザ自動化フレームワークを日常的に使い分ける不便を低減し、ユーザーが利用するブラウザを、特定の AI サービス、AI プロバイダ、AI モデル、エージェント実行環境、クライアントアプリケーション又はツールプロトコルにロックインされることなく、一又は複数の AI エージェントと柔軟に連携させるブラウザＡＩ連携システムを提供することである。さらに、本発明の課題は、ユーザーが明示的に許可した対象のみを AI エージェントに共有し、当該対象の取得対象識別情報の変化、対象の終了、又は明示的取消しに応じて共有許可を失効させ、共有許可済み対象上でユーザーが領域、テキスト、又は構造化要素を注釈として指定できるようにするとともに、Gateway を通過する送受信内容及び操作要求を監査可能にすることである。

【0025】

【発明の効果】

【0034】

【0051】

注釈レイヤ100は、Area モード及び Text モードを有する。Area モードでは、ユーザーがブラウザタブ40上でドラッグした矩形領域、又はクリックした点を注釈入力として受け付ける。Text モードでは、ユーザーが複数の構造化要素にまたがる本文を選択した場合であっても、選択文字列を注釈入力として受け付ける。ユーザーは、注釈入力にコメントを付与し、Done ボタン又は Escape キーにより注釈レイヤ100のキャプチャを停止できる。停止後も注釈データ110は保持され、AI エージェント90はエージェント操作インターフェース30により当該注釈データ110を取得できる。

【0067】
ブラウザ操作連携機能10は、Area モードで指定された領域について、領域の中心点、対象要素の表示矩形、安定した属性、及び意味のある要素種別を用いて、当該領域が安定した構造化要素に対応するかを判定する。安定した構造化要素に対応する場合、ブラウザ操作連携機能10は当該注釈を構造要素注釈として分類し、対象要素識別情報、識別品質、タグ名、表示文字列、色、背景色、フォントサイズ及びフォントファミリ等を注釈データ110に含める。canvas、video、又は曖昧な wrapper のように安定した構造化要素を推定しにくい場合、ブラウザ操作連携機能10は当該注釈を視覚領域注釈として分類し、位置情報を注釈データ110に含める。

【0068】
ブラウザ操作連携機能10は、Text モードで指定された選択文字列について、選択文字列、当該選択文字列のルート要素識別情報、範囲情報、ハイライト断片、並びに再特定用のインデックス等を含む再特定情報を注釈データ110に含める。テキスト注釈は矩形枠ではなく、選択文字列の行ごとのハイライトとして注釈レイヤ100上に表示される。これにより、AI エージェント90は、視覚領域としてではなく、純粋なテキストデータとして選択内容を受け取ることができる。

【0069】
構造要素注釈及びテキスト注釈は、対象要素識別情報又は再特定情報への追従性を維持するため、注釈レイヤ100上で移動又はリサイズされない。一方、視覚領域注釈は、任意の視覚領域を示すため、ドラッグによる移動及び辺又は角のハンドルによるリサイズを許容する。ブラウザ操作連携機能10は、スクロール、リサイズ、iframe 内スクロール、又はレスポンシブレイアウト変更に応じて注釈レイヤ100を再描画し、各注釈の位置情報を更新する。

【0070】
エージェント操作インターフェース30は、注釈レイヤ100について、開始、停止、消去、一覧取得、対象要素識別情報による構造要素注釈追加、及び位置情報による領域注釈追加を提供する。領域注釈追加の結果が視覚領域注釈である場合、エージェント操作インターフェース30は当該領域に対応する画像を保存してもよい。注釈一覧の戻り値には、注釈種別、コメント、位置情報、対象要素情報、選択文字列、再特定情報、取得対象識別情報、表示対象識別情報、及び作成時刻の少なくとも一つが含まれる。

【0071】
注釈レイヤ100は、AI エージェント90による操作の事前確認にも利用できる。例えば、AI エージェント90がボタン、ロゴ、入力欄、又は任意の視覚領域を操作又は差し替えの対象として提案する場合、ユーザーは当該対象を注釈として指定し、AI エージェント90は注釈データ110に含まれる対象要素情報又は位置情報を用いて後続の読み取り、画像取得、一時的な表示内容変更、又は承認付き書き込み操作を行うことができる。これにより、人間が「ここ」と指示した対象を、AI エージェント90が構造化された対象情報として扱うことができる。

【0072】
ブラウザ操作連携機能10は、注釈レイヤ100を実行する際、まず第1のブラウザ連携機構による実行を試行する。当該実行が、AI ブラウザ又はブラウザ相当環境における権限又は実行環境の制限により拒否された場合、ブラウザ操作連携機能10は、共有許可済みタブ40に対して、第2のブラウザ連携機構により注釈レイヤ100を実行する。第1及び第2のブラウザ連携機構には、例えばブラウザアドオン API、ブラウザ連携 API、デバッグプロトコル、リモート制御プロトコル、又はこれに相当するブラウザ制御 API のスクリプト評価機能が含まれる。

第3実施形態

【0073】
第3実施形態は、同一装置内通信のセキュリティ強化構成である。図9に示すように、Gateway モジュール20は、接続要求を受けた場合、接続を実質的に受け入れてメッセージ処理を開始する前に、発信元検証部120により当該接続要求の発信元識別情報又は認証情報を検証する。接続要求が WebSocket 接続要求である場合、発信元検証部120は、例えば Origin の scheme が `chrome-extension`、`moz-extension`、`safari-web-extension`、又はブラウザ操作連携機能に対応するブラウザ固有の scheme のいずれかであり、かつ host が存在し、ユーザー情報、パス、クエリ、及びフラグメントを含まない場合に限り、許可されたブラウザ連携元と判定する。

【0074】
発信元検証部120は、発信元識別情報又は認証情報が欠落している場合、空である場合、通常の Web ページ等の許可されない発信元を示す場合、又は許可されたブラウザ連携元に似せた不正形式を含む場合には、当該接続要求を拒否する。これにより、許可されない発信元が同一装置内通信路を介して Gateway モジュール20を操作する経路を遮断できる。

【0075】
Gateway モジュール20は、アプリケーションサポートディレクトリ、ログディレクトリ、同一装置内通信路、及び監査記録60について、所有者ユーザーのみがアクセス可能な権限を設定することができる。例えば、アプリケーションサポートディレクトリ及びログディレクトリは所有者ユーザーのみがアクセス可能な権限とし、監査記録60は所有者ユーザーのみが読み書き可能な権限とする。監査記録60は、例えば JSONL 形式で追記され、読み取り、書き込み、注釈、共有許可付与、失効、接続状態の変化、Gateway モジュール20が受信又は返送した内容の要約情報、ハッシュ値、秘匿化理由、及び拒否理由を記録する。

【0076】
Gateway モジュール20に対応するテストは、許可されたブラウザ連携元を許可する場合、許可されない発信元又は欠落した発信元識別情報を拒否する場合、及び許可されたブラウザ連携元に似せた不正形式を拒否する場合を含む。これにより、発信元検証部120の境界条件を実装段階で検証できる。

第4実施形態

【0077】
第4実施形態では、ブラウザは、Chrome、Safari、Firefox 等の複数種類のブラウザ、又はこれらに準ずるアドオン機構、ブラウザ内蔵の追加機能、若しくはブラウザ画面に対する外部操作連携部を有するブラウザであってよい。ブラウザ操作連携機能10は、各ブラウザのアドオン API、ブラウザ連携 API、又は外部操作連携 API に応じて実装される。ブラウザが提供するデバッグプロトコル、リモート制御プロトコル、又はブラウザ固有のデバッグ API が利用可能な場合、ブラウザ操作連携機能10は当該プロトコル又は API を用いて読み取り、注釈、又は操作を実行する。利用可能でない場合、ブラウザ操作連携機能10は、共有許可済みタブに対する構造化された限定的なスクリプト注入、又は共有許可済みタブに対応する表示領域若しくは画面内座標に限定された外部操作連携により読み取り、注釈、又は操作を実行する。

【0078】
Gateway モジュール20は、ブラウザと同一のデスクトップオペレーティングシステム上で動作してもよく、スマートフォン又はタブレット等のモバイル端末上で動作してもよく、クラウドサーバー、クラウド環境上の常駐サービス、私設ネットワーク上のサーバー、オンプレミスサーバー、又は組込み環境上で動作してもよい。Gateway モジュール20は、ブラウザ内、ブラウザのアドオン機構内、オペレーティングシステム内、AI エージェント実行環境内、ネイティブアプリケーション内、サーバー上、クラウド環境上、又はこれらの組み合わせとして実装されてもよい。エージェント操作インターフェース30は、Unix Domain Socket に限らず、名前付きパイプ、ローカル TCP ソケット、WebSocket、HTTP、gRPC、標準入出力、USB 接続、Bluetooth 接続、近距離無線接続、ローカルネットワーク、私設ネットワーク、仮想私設ネットワーク、インターネット、又は OS 固有のローカル若しくはリモート IPC を用いて Gateway モジュール20と通信してよい。例えば、スマートフォン上のモバイルブラウザ拡張がブラウザ操作連携機能10として動作し、Gateway モジュール20が当該スマートフォン、近傍のデスクトップ端末、私設ネットワーク上のサーバー、又はクラウド環境上で動作する構成であってよい。

【実施例1】

【0079】
実施例1では、通常のブラウザタブで開いている日本語 CMS 記事をユーザーがブラウザ操作連携機能10のアドオン UI から共有許可し、本実施例で用いた実装において AI エージェント90が `abg read <tab> --selector article --format markdown` に相当するコマンドを実行した。比較対象として、ブラウザ自動化フレームワークによるページ全体 HTML 取得、`article` 要素の `innerHTML` 取得、及び `article` 要素の `innerText` 取得を用いた。測定は、公開記事を対象として ABG リポジトリのベンチマークにより実施した。

【0080】
測定結果は、ページ全体 HTML 取得では文字数124,476字、概算トークン数約50,000であり、構造は保持されるもののオーバーヘッドが大きかった。`article` 要素 `innerHTML` 取得では文字数42,070字、概算トークン数約17,000であり、構造は保持されるもののマークアップのオーバーヘッドが残った。本実施例の `abg read N --selector article --format markdown` に相当する処理では文字数11,780字、概算トークン数約5,900であり、構造を保持しつつ整形済みの出力を得た。一方、`article` 要素 `innerText` 取得では文字数6,543字、概算トークン数約3,800であったが、見出し、リンク及びリスト等の構造が失われた。

【0081】
この結果から、`abg read N --selector article --format markdown` は、ページ全体 HTML 取得と比較して、文字数ベースで約90.5%削減し、概算トークン数ベースで約88%削減した。一方で、`innerText` 取得と異なり、見出し、リンク、リスト等の構造は保持された。したがって、本実施形態は、共有許可済みタブに限定した安全な連携に加え、AI エージェント90へ渡す文脈情報量を大幅に低減する効果を有する。

【実施例2】

【0082】
実施例2では、ナレッジベース型ページのフィクスチャを用い、汎用 `markdown-plugin` と、ドメイン別プラグインとを比較した。ドメイン別プラグインは、プラグイン定義において特定のドメイン条件を有し、Gateway モジュール20が共有許可済みタブの URL と当該ドメイン条件とを照合したうえで、汎用変換より前にドメイン別変換を実行する。

【0083】
測定結果は、ナレッジベース型ページの未加工 HTML では文字数2,209字、概算トークン数約553であったのに対し、汎用 `markdown-plugin` では文字数1,242字、概算トークン数約311となり、未加工 HTML 比で約44%削減した。ドメイン別変換では文字数709字、概算トークン数約178となり、未加工 HTML 比で約68%削減した。

【0084】
この結果から、ドメイン別プラグイン50は、汎用 HTML 変換よりもさらにページ固有の不要要素を削減し、未加工 HTML 比で約68%のトークン削減を実現した。これにより、AI エージェント90は、アプリケーションのサイドバー、ポップオーバー、スクリプト、スタイル等のノイズではなく、業務上意味のある本文に集中できる。
