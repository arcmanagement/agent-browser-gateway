Artifact Provenance

Each public ABG artifact should be traceable to a source tag, a build command, a checksum, and the public build or release record that produced it.

Release tags Artifacts Build logs Rebuild Signing boundary

1. Release tags

A release version X.Y.Z maps to the source tag vX.Y.Z in the GitHub repository. Start provenance checks from the tag page:

github.com/arcmanagement/agent-browser-gateway/releases 

$ git fetch --tags origin
$ git checkout vX.Y.Z
$ git rev-parse HEAD

2. Artifact map

Artifact Source Produced by
agent-browser-gateway-X.Y.Z-macos-arm64.zip vX.Y.Z make dist VERSION=X.Y.Z
agent-browser-gateway-X.Y.Z-macos-arm64.dmg Same staged macOS payload as the ZIP make pages-dmg VERSION=X.Y.Z
agent-browser-gateway-extension-X.Y.Z.zip extension/dist/ from the tag scripts/dist-macos-arm64.sh
agent-browser-gateway-X.Y.Z-windows-x64.zip Windows projects under windows/ scripts/dist-windows-x64.ps1
agent-browser-gateway-X.Y.Z-windows-x64-setup.zip Windows setup project under windows/ scripts/dist-windows-x64.ps1
agent-browser-gateway.rb macOS ZIP checksum for the release scripts/dist-macos-arm64.sh

Public checksum files use the same artifact basename with .sha256.txt appended and are published next to the download.

3. Build logs

Use GitHub Actions logs to confirm the tag or branch built cleanly. Filter workflow runs by the release ref when reviewing a specific release.

  • macOS and extension verification: CI workflow
  • Windows build and packaging verification: Windows CI workflow
  • Public site publication: GitHub Pages workflow

For release X.Y.Z, use the Actions search filter ref:vX.Y.Z where a workflow run exists for that tag.

4. Local rebuild

Unsigned rebuilds can confirm the source and build scripts. They are not expected to match signed release bytes exactly. 

$ git checkout vX.Y.Z
$ mise trust
$ mise install
$ cd extension && pnpm install --frozen-lockfile && cd ..
$ make dist VERSION=X.Y.Z

Windows artifacts are rebuilt on Windows with .NET 8: 

PS> .\scripts\dist-windows-x64.ps1 -Version X.Y.Z

5. Signing and notarization boundary

Developer ID signing, notarization, stapling, DMG compression, ZIP metadata, and timestamped signatures are not byte-for-byte reproducible by third parties. ABG keeps signing credentials off GitHub Actions; signed public assets are produced on a trusted maintainer Mac and then uploaded with checksums.

Verify the source tag, inspect the public workflow logs, compare the published SHA-256 checksum, and use platform trust checks such as codesign, spctl, and notarization assessment for signed macOS artifacts.
