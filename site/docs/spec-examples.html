Architecture and Token Economy

ABG keeps the consent boundary in the extension and Gateway, while the CLI and plugin host turn noisy browser state into compact agent input.

Architecture CDP boundary Token benchmark Plugin example

1. Architecture

ABG is split into four pieces with different trust responsibilities.

Layer Responsibility Boundary
Browser extension Owns tab sharing, optional all-tabs permission, page operations, screenshots, console, network, and DOM access. No default host permissions; manual sharing is per-tab.
Gateway Accepts browser-extension WebSocket connections, tracks permitted tabs, dispatches commands, and writes local audit logs. Binds to 127.0.0.1 and accepts extension origins only.
Plugin host Runs bundled and user-installed JavaScript transformers or commands inside the local Gateway process. User plugins are local code and must be explicitly installed from trusted sources.
CLI Provides the stable agent-facing API for read, tabs, screenshot, actions, plugins, and audit inspection. Agents can address only tabs currently permitted by the Gateway.

2. Why CDP still fits per-tab consent

ABG uses Chrome extension APIs and Chrome debugging APIs for some operations, but the permission decision happens before any operation reaches those APIs. The extension sends tab updates only for tabs the user shared manually, or for all shareable tabs in an isolated profile after explicit all-tabs opt-in.

The Gateway rejects commands for tabs that are not in its live permission list. That means CDP-backed features such as screenshots, PDF capture, network inspection, and input dispatch inherit ABG's per-tab consent gate instead of creating a global remote debugging port for the whole browser profile.

3. Token-economy benchmark

On a representative Japanese WordPress article, ABG's Markdown read preserves headings, links, and list structure while removing scripts, styles, and layout noise.

Method Chars Tokens approx. Structure
Playwright page.content() 124,476 ~50,000 Preserved with massive overhead
Playwright locator('article').innerHTML() 42,070 ~17,000 Preserved with overhead
abg read --selector article --format markdown 11,780 ~5,900 Preserved and clean
Playwright locator('article').innerText() 6,543 ~3,800 Headings, links, and lists lost

At 1,000 reads with Claude Opus input pricing, the naive Playwright full-HTML path is about $750 of input, while ABG Markdown is about $88. That is roughly an 88% reduction while keeping useful document structure.

4. Plugin example

The bundled Notion plugin shows the same architecture at per-domain scope. It trims app chrome, scripts, styles, sidebars, popovers, and bookkeeping attributes before the agent sees the page. 

$ node examples/benchmark-notion-plugin.mjs

In the included fixture, generic Markdown reduces the raw page by 44%; the Notion domain transform reduces it by 68%.
