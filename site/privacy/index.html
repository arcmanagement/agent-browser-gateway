Privacy Policy

This policy explains how Agent Browser Gateway handles browser data, extension permissions, local logs, and user choices.

Last updated: May 28, 2026

Scope Summary Data handled Permissions Sharing Security Retention Choices Limited Use Contact

1. Scope

This Privacy Policy applies to Agent Browser Gateway ("ABG"), managed by ArcManagement, Inc. ("ArcManagement", "we", "our", or "the product"), including the Agent Browser Gateway Chrome extension, the macOS Agent Browser Gateway app, the abg command-line interface, locally installed ABG plugins, and the website at agent-browser-gateway.com.

ABG is designed as a local bridge between your browser and AI agent tools you choose to run. ABG does not operate a hosted browser service or a cloud account system.

2. Summary

  • ABG does not collect analytics, telemetry, advertising identifiers, or crash reports.
  • ABG does not sell user data.
  • ABG does not expose all tabs by default. A tab must be explicitly shared by the user, unless the user enables optional all-tabs mode for an isolated profile.
  • Browser data requested through ABG is handled locally between the extension, the macOS gateway, the CLI, and the agent process you authorize.
  • If you use ABG with an AI agent or another tool that sends data to a third-party service, that service's own terms and privacy policy apply to what you send through it.

3. Data ABG handles

ABG can handle browser data only for tabs you choose to share or commands you choose to run. The table below describes the main categories of data involved.

The public website does not use forms, cookies, analytics scripts, advertising tags, or tracking pixels. The website may be hosted by GitHub Pages, which may process standard server logs such as IP addresses and request metadata for security and service operation according to GitHub's own policies.

4. Chrome extension permissions

ABG requests only the extension permissions needed for its user-facing local browser sharing features. The extension declares no default host_permissions. Optional <all_urls> access is requested only when the user enables all-tabs mode from the extension popup.

Permission Why ABG uses it
activeTab Access the active tab only when the user explicitly shares it.
scripting Read selected page content and perform structured operations in a shared tab.
tabs Read tab title, URL, and lifecycle events so ABG can list and revoke shared tabs.
storage Store local settings and session-scoped tab sharing state.
debugger Capture screenshots, console messages, network information, file uploads, and input operations for a tab the user has shared.
alarms Keep the extension service worker connected to the local gateway while Chrome is running.
optional_host_permissions: <all_urls> Requested only when the user enables all-tabs mode for an isolated Chrome profile. It is removed when all-tabs mode is disabled.

5. Data sharing and third parties

ABG does not send browser data to servers operated by ABG. Data moves locally between the Chrome extension, the macOS gateway, the abg CLI, and the local agent process or shell command you authorize.

ABG is agent-agnostic. If the agent tool you use sends prompts, screenshots, page content, logs, or other information to a remote AI provider or third-party service, that transfer is performed by that agent or service, not by ABG. Review the privacy policy and configuration of the agent you use with ABG.

ABG may include locally installed plugins. Plugins can transform page content before it is returned to the CLI. Install plugins only from sources you trust.

6. Security measures

  • The gateway listens on 127.0.0.1, not on a public network interface.
  • The gateway accepts WebSocket connections only from browser-extension origins.
  • The Chrome extension declares no default host_permissions.
  • Manual tab sharing is scoped to explicitly permitted tabs and is revoked on origin change or tab close.
  • Operation approval mode is enabled by default for write actions.
  • The gateway support and log directories are created as owner-only directories.
  • The audit log file is created as an owner-readable and owner-writable file.
  • General JavaScript eval is disabled by default and limited to explicitly shared tabs after local user enablement. Per-call approval is the default; Trusted automation / AutoMode can skip the popup while preserving audit logging.

7. Retention

  • Extension settings remain in Chrome local storage until changed, reset, or uninstalled.
  • Shared tab state is session-scoped and can be cleared by revoking a tab or restarting Chrome.
  • Console and network buffers are held in extension memory and cleared when a tab is revoked or closed.
  • Audit log entries remain on your Mac until you delete them.
  • Screenshots saved by the CLI remain at the output path until you delete them.

8. Your choices

  • Do not share a tab unless you want the local agent workflow to inspect or operate it.
  • Use the extension popup or abg revoke to revoke a shared tab.
  • Keep operation approval mode enabled for a second local confirmation step.
  • Review local audit logs with abg audit or by opening the audit log file.
  • Delete local screenshots or audit logs from your Mac when you no longer need them.
  • Uninstall the Chrome extension and macOS app to stop using ABG.

9. Chrome Web Store Limited Use disclosure

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.

ABG uses browser data only to provide or improve its single purpose: user-authorized, local browser access for AI agent workflows. ABG does not use browser data for advertising, credit eligibility, resale, or unrelated profiling.

10. Changes to this policy

We may update this policy as ABG changes. Material updates will be reflected by the "Last updated" date above. If a future version changes how user data is collected, used, stored, or shared, the policy and Chrome Web Store disclosures should be updated before that version is published.
