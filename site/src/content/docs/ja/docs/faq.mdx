よくある質問に短く答えます。困ったときに引かれやすい質問を先に並べました。

## エージェントがタブを見つけられません。何を確かめればよいですか？

次の順に実行します。

```bash
abg status
abg tabs --compact
abg audit --lines 20
```

タブを閉じた、別のオリジンへ移動した、共有を解除した、のいずれかが考えられます。拡張機能のポップアップからタブを共有し直し、`abg tabs --compact` で今の `ref` を確かめます。エラーコードごとの対処は[うまくいかないとき](../#うまくいかないとき)を参照してください。

## タブの ref が変わったのはなぜですか？

`ref` は1回の共有ごとに割り当てられます。共有を解除してから共有し直したタブには、`t2` のような新しい `ref` が付きます。Gateway を再起動したときも変わることがあります。`abg tabs --compact` で今の値を確かめてください。

## シークレットウィンドウでも使えますか？

使えます。拡張機能の詳細画面で **Allow in incognito** をオンにしてください。Chrome は初期設定では、シークレットウィンドウで拡張機能を動かしません。

## ABG を更新するには？

- Homebrew: `brew upgrade --cask agent-browser-gateway`
- DMG: 新しい DMG をダウンロードし、**Install Agent Browser Gateway.app** をもう一度実行します。
- エージェントスキル: `npx skills update -g`

## エージェントは全タブを見られますか？

初期設定では見られません。エージェントに見えるのは、共有したタブだけです。全タブ共有モードは、隔離したプロファイルやサンドボックス用のマシン向けに別途オンにするモードです。

## ABG はブラウザーのデータをクラウドに送りますか？

ローカル接続は `127.0.0.1`、または本人が許可した非公開のスマートフォン接続を使います。拡張1.1.3のCloud接続では、共有した内容と要求した結果を、選択したサービスを通して許可済みAI連携へ渡します。Webログインを使い、デスクトップアプリは不要です。どちらも広告・分析用テレメトリーは追加しません。[Cloud手順](https://github.com/arcmanagement/agent-browser-gateway/blob/main/docs/CLOUD_EXTENSION.md)を参照してください。

## どのエージェントで使えますか？

Claude Code、Codex、Cursor、Cline など、シェルのコマンドを実行できるエージェントなら使えます。Claude Code と Codex にはスキルもあります。`npx skills add arcmanagement/agent-browser-gateway -g` で入れてください。

## MCP に対応していますか？

はい。`abg mcp-server` は、ローカルの CLI を呼ぶ `abg_cli` ツールを1つだけ公開する stdio の MCP サーバーです。基準は CLI のままです。シェルを使えるエージェントならどれでも使え、人もそのまま動きを確かめられます。[エージェントスキルと MCP](../install/#エージェントスキルと-mcp) を参照してください。

## Cloud接続が切れた原因を調べるには？

拡張1.1.3の **詳細設定 → 接続履歴** から **JSONを保存** を選びます。直近7日間・最大200件の切断コード、認証失敗、意図した切断などをブラウザー内に保存し、再起動後も確認できます。認証情報やページ内容は含まれません。1006だけではネットワークとサービスの障害を区別できないため、UTC時刻でサービスログと照合します。[診断ガイド](https://github.com/arcmanagement/agent-browser-gateway/blob/main/docs/CLOUD_EXTENSION.md#connection-diagnostics)を参照してください。

## ABG は Playwright の代わりになりますか？

なりません。自動化の側が持つ、まっさらで再現できるブラウザーが欲しいなら Playwright を使います。ABG は、すでに使っているブラウザーのセッションから、タブを1つ、または隔離した全タブ共有のプロファイルをエージェントに渡すための道具です。

## プラグインはどこに保存されますか？

同梱のプラグインはアプリの中にあります。ユーザーが入れたプラグインは `~/.abg/plugins/` に置かれます。ポート `8766` の開発版 Gateway では `~/.abg-dev/plugins/` を使います。

## プラグインの設定はデータベースに保存されますか？

されません。プラグインの有効・無効は、使用中の ABG ユーザーディレクトリにある `plugin-state.json` に保存します。

## 非公開のプラグインリポジトリはどう認証しますか？

`abg plugin install` は手元の `git` コマンドを使います。非公開リポジトリでは、既存の SSH 鍵、git の認証情報ヘルパー、GitHub CLI と連携した git 認証を使います。ABG は GitHub のトークンを求めず、保存もしません。
