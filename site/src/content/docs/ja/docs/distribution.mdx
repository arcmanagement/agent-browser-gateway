配布経路ごとのバージョンを確かめ、ダウンロードしたファイルを検証し、署名済みのリリースをビルドします。

## 現在のリリース状況

| 配布経路 | 状況 |
| --- | --- |
| macOS アプリ: GitHub Releases、Homebrew | 署名と公証を済ませた `v0.5.2` |
| Chrome ウェブストア | 拡張機能 `v0.4.8`。更新日は2026年8月23日（`v0.5.2` は審査中） |
| Windows: WinGet、セットアップ ZIP | 署名済みの Windows リリースと WinGet への登録待ち |

Chrome ウェブストアの審査と署名済みアプリの公開はそれぞれ別に進むため、アプリと拡張機能のバージョンが食い違うことがあります。

## ダウンロードの検証

成果物とチェックサムファイルを同じリリースからダウンロードし、ハッシュを確かめます。`X.Y.Z` はリリースのバージョンに置き換えます。

```bash
shasum -a 256 -c agent-browser-gateway-X.Y.Z-macos-arm64.dmg.sha256.txt
```

`SHA256SUMS.txt` を公開しているリリースでは次のように確かめます。

```bash
shasum -a 256 -c SHA256SUMS.txt --ignore-missing
```

チェックサムが一致した成果物だけをインストールしてください。チェックサムファイルがない、またはハッシュが一致しない場合は、作業を止めて GitHub に issue を立ててください。

インストール後、初めて起動する前にアプリの署名を確かめます。

```bash
codesign --verify --strict --verbose=2 "/Applications/Agent Browser Gateway.app"
spctl --assess --type execute --verbose "/Applications/Agent Browser Gateway.app"
```

## 配布経路

### Homebrew cask

cask は `Agent Browser Gateway.app` を `/Applications` に、`abg` を Homebrew の `bin` に入れます。

```bash
brew tap arcmanagement/agent-browser-gateway https://github.com/arcmanagement/agent-browser-gateway
brew trust --cask arcmanagement/agent-browser-gateway/agent-browser-gateway
brew install --cask agent-browser-gateway
```

最新版がインストール済みと表示された場合、cask の経路は正しく動いており、更新は不要です。

Homebrew 向けのリリースが整う条件は2つです。対応する GitHub Release にバージョン付きの macOS ZIP が公開されていることと、このリポジトリの `Casks/agent-browser-gateway.rb` がそのバージョンと SHA-256 を指していることです。

### Chrome ウェブストア

[Chrome ウェブストアの公開ページ](https://chromewebstore.google.com/detail/agent-browser-gateway/ojgedfcgebjchckaagjkmlpgonpjggpi) から拡張機能を入れます。

リリースの検証では、公開ページが開けることを確かめ、表示されたバージョンと更新日を最新の macOS リリースとは別に記録します。現在の表示はバージョン `0.4.8`、更新日は2026年8月23日です。拡張機能 `v0.5.2` は審査中です。

### WinGet

```powershell
winget install --id ArcManagement.AgentBrowserGateway --source winget
```

`v0.5.2` はまだ WinGet に登録されていません。署名済みの Windows リリースのワークフローと WinGet への申請が済むまで、このコマンドは一致するパッケージなしを返します。

WinGet 向けのリリースが整うのは、公開用の Windows セットアップ ZIP が GitHub Releases に置かれ、そこから生成した `microsoft/winget-pkgs` の PR がマージされて登録されたあとです。

### Mac App Store

Mac App Store の経路は、Developer ID と Homebrew のリリース経路とは別です。ストア向けのビルドは App Sandbox と App Store 配布用の署名を使い、App Store Connect にアップロードします。手順の一覧は `docs/app-store-submission.md` にあります。

## メンテナー向けリリースビルド

### 署名済み成果物のビルド

信頼できる Mac 上で、Developer ID の署名と公証を済ませた成果物をビルドします。

```bash
export VERSION=0.5.2
make release-dmg VERSION="$VERSION" \
  SIGN_IDENTITY="Developer ID Application: ArcManagement Inc (M46W5MVAQP)" \
  NOTARY_PROFILE="abg-notary"
```

`make release-dmg` は先に `make dist` を実行するため、macOS ZIP、DMG、拡張機能の ZIP、生成された cask がまとめて `dist/` に出力されます。

Developer ID の署名は手元の Mac だけで行います。Developer ID の秘密鍵、証明書のパスワード、App Store Connect の認証情報、`notarytool` の認証情報を GitHub Actions のシークレットに入れないでください。

### 成果物の検証

```bash
codesign --verify --strict --verbose=2 \
  "dist/agent-browser-gateway-$VERSION-macos-arm64/Agent Browser Gateway.app"
codesign --verify --strict --verbose=2 \
  "dist/agent-browser-gateway-$VERSION-macos-arm64/abg"
spctl --assess --type execute --verbose \
  "dist/agent-browser-gateway-$VERSION-macos-arm64/Agent Browser Gateway.app"
shasum -a 256 \
  "dist/agent-browser-gateway-$VERSION-macos-arm64.zip" \
  "dist/agent-browser-gateway-extension-$VERSION.zip"
```

CI では署名なしの成果物をビルドしてテストできます。署名済みのリリース成果物は信頼できるメンテナーの Mac で作り、公開前の下書きの GitHub Release にアップロードします。

### 再現可能ビルドの試行

v1.0 のリリース前に、署名なしの再現可能ビルドを試せます。

```bash
make reproducible-build
```

`dist/reproducible-build/` に、拡張機能と Gateway の比較用成果物、`SHA256SUMS.txt`、`BUILD_INPUTS.txt`、`agent-browser-gateway-$VERSION.spdx.json` が出力されます。チェックサム、署名、SBOM、来歴、利用者による検証の計画は [`docs/RELEASE_ARTIFACT_TRUST.md`](https://github.com/arcmanagement/agent-browser-gateway/blob/main/docs/RELEASE_ARTIFACT_TRUST.md) にあります。
